# context/ — drop everything here

This folder is where you brief your new colleague. **Messy is fine.** Half-sentences, voice-memo transcripts, a paragraph pasted from an old grant application — all of it works, because the agent's first job (Phase 1) is to read this folder, rephrase what it thinks you want, and then *interview you* about whatever is missing. You don't need to write a good prompt. You need to dump what exists.

Useful things to drop, if they exist (skip freely — gaps just become interview questions):

- **The question**, in any form: a sketch, an abstract, an email to a coauthor, bullet fragments.
- **Protocol / pre-registration**, if there is one — this changes everything downstream, so it's the first thing the interview will ask about.
- **Data description**: codebook, variable list, a sample of rows, where the data comes from, who is allowed to see it. *(If any data is confidential, licensed, or human-subjects, say so here or in the interview — it changes where the data may live, and the agent will respect that line absolutely.)*
- **What already exists**: old scripts, a draft, a results table from a pilot.
- **Constraints**: deadline, target journal or audience, software you must/can't use.
- **Anything you'd tell a new collaborator on day one** — including the things that feel too obvious to write down. Those are usually the ones that matter.

When you're done dumping: open Claude Code in the project folder and **say hello — in your own words.** Tell it what you brought, or just ask where things stand; it takes it from there. (Typing `/start` does the same, for people who like buttons.)
